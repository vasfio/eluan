## Decisions I was unsure about

- Panel content: the task names the three views but gives no content, so the panels are required `ReactNode` props (`overview`, `activity`, `settings`) instead of placeholder text I'd have to make up.
- `aria-label` on TabsList: the doc says to add one "when the tabs need context". I made it an optional `label` prop that defaults to "Sections" so the tablist is always named. A generic default might be worse than no label, and the caller should really pass something like "Project sections".
- Uncontrolled (`defaultValue="overview"`) rather than exposing `value`/`onValueChange`: nothing asked for linkable tabs or URL sync, so I didn't add controlled mode.
- Mounting: inactive panels unmount, which would drop an unsaved Settings form. I documented "lift state above this component" in the JSDoc rather than using `forceMount`. tabs.md doesn't say whether Eluan hides force-mounted inactive panels, and with plain Radix they stay visible.
- No icons on the triggers, even though lucide-react is installed: the content guidelines allow icons only next to text and nothing called for them, so I didn't read foundations/iconography.md.
- No heading inside the component: navigation.md says tabs sit directly under the heading of the thing they switch. That heading belongs to the page using the component, so it's left to the caller and mentioned in the JSDoc.
- Explicit JSX for the three trigger/panel pairs instead of mapping over a config array: it's clearer for a fixed set of three and matches the doc examples, but it means the values are written twice.
