## Decisions I was unsure about

- Spacing before the action: the pattern says "gap `--spacing-sm`, `--spacing-lg` before the action", but its example puts `marginTop: --spacing-lg` on the button wrapper inside the `sm` gap, which makes sm + lg. I used two nested flex columns (outer gap `lg`, inner group gap `sm`) so the space before the button is exactly `lg`, with gap instead of margin (spacing rule 4). That's slightly tighter than the example renders.
- Icon colour: the pattern example sets `color` directly on the Lucide SVG. Iconography rule 3 says to set it on the parent. I followed the foundation rule and put `color: var(--container-fg-alt)` on a wrapper `span`. It looks the same but adds one element.
- Icon size: used `--size-md` (pattern, and the top of iconography's `--size-sm` to `--size-md` range for empty states) rather than `--size-sm`.
- Heading level: the pattern says to use "the right heading level for the page", and I don't know the dashboard's outline. I defaulted to `h2` (assuming the page title is the `h1`) and added a `headingLevel` prop (`h2` | `h3` | `h4`).
- Centring text: used Typography's `align="center"` prop instead of `textAlign: center` on the wrapper as in the pattern example, preferring the component prop. The result should be the same.
- No Card or surface around the empty state: pattern rule 3 says to keep it inside the region it replaces, so it renders bare and the parent supplies the region. I didn't read `card.md`.
- Loading and error states: left to the parent and documented in JSDoc (Skeleton while loading, destructive Banner on failure) instead of handled in this component, so I didn't read `skeleton.md` or `banner.md`. A teammate might have expected one component covering all three states.
- Action wiring: an `onCreateProject` callback on a `type="button"` Button (primary/default variant, first use). The other option was a link to a create route via Button `asChild`. I don't know whether creation is a route or a Dialog.
- No `Plus` icon inside the button: it would repeat the decorative FolderPlus. The Button doc shows one in a toolbar example, but the empty-state example has none.
- Copy: "No projects yet" / "Create your first project to get started." / "Create project". Close to the pattern's wording. The body and button both say "create", which is a little repetitive.
- Skipped `foundations/typography.md` even though SKILL.md rule 5 says to read the matching foundation before any visual decision. My reasoning: every text style comes from Typography variants the pattern names (`subheading`, `body` with `tone="muted"`), so I made no type decision of my own. This may be a stricter-reading miss.
- Styles live in a typed inline style object (`satisfies Record<string, CSSProperties>`) on plain elements I own, not on Eluan components (rule 7). SKILL.md lists inline styles as an accepted option, but the host app may prefer StyleX or CSS modules.
- No `max-width` on the body text for line length: every way I could think of (ch, rem, px) breaks the no-raw-units rule, and no `--size-*` token fits. The copy is one short line, so I left it out.
