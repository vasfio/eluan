## Decisions I was unsure about

- **Styling method.** I used inline `style` objects that read tokens, not `stylex.create`. The installation page says consumers need no StyleX setup, and the tokens page says a `style` attribute is a valid place for tokens. I can't confirm the app has the StyleX compiler, and without it `stylex.create` would throw at runtime. The cost is no media queries.
- **Responsive layout without media queries.** I used the flex-wrap "switcher" trick (`flex-basis: calc((52rem - 100%) * 999)`): one row when all three plans fit, one column when they don't, never a 2 + 1 split. The 52rem threshold is a judgement call (about 16rem per card plus gaps).
- **How the middle plan stands out.** I only used documented levers: Card `elevation="lg"` (the others keep the default `"sm"`), a default-variant `Badge` reading "Recommended", and a filled `default` Button (the others use `outline`). Components are closed to className/style, so I couldn't add an accent border or scale. I also skipped scoping a token override such as `--container-border` around the card, because the docs don't say which token Card's border reads.
- **Elevation for the other plans.** I chose `"sm"` (the default) over `"none"`. `"none"` would give more contrast but would make these cards differ from Cards elsewhere in the app.
- **Badge variant.** I used `default`. `important` or `informative` were the alternatives, but the docs don't say which one means "recommended".
- **CTA position.** I put the CTA under the price inside `CardContent`, not in `CardFooter`. I can't make Card a flex column, so a footer would sit at a different height on each card whenever the feature lists differ in length. The cards do match in height, because each `li` is a grid container that stretches its Card. That relies on Card not setting its own height or align-self, which I couldn't check.
- **Typography `asChild` on `<li>`.** I used it so each feature row gets body type and the check icon can be exactly `1lh` tall. That assumes Radix Slot merges the child `li`'s own `style` (it normally does). `1lh` needs a fairly recent browser; where it isn't supported the icon just aligns to the top.
- **Check icon colour.** I used `--container-fg-alt` (muted). `--positive-fg` was the alternative, but its documented role is status text, and I can't tell whether it is readable on `--container-bg`.
- **Spacing tokens.** I used the documented `--spacing-*` aliases (they follow the `data-spacing` density setting), not the `--space-*` names in the docs demos. `globals.css` says `--space-*` exists only in the docs site and is not part of Eluan.
- **Docs inconsistency.** The Card page says sub-components "extend their respective HTML element props", but Getting Started says components don't accept `className` or `style`. I followed the stricter rule and passed only `id` (to CardTitle and Typography) as an HTML prop.
- **Scope.** I didn't add a monthly/annual toggle because it wasn't asked for. Plans are typed data with a `recommended` flag and an optional `plans` prop, so the highlight isn't tied to "index 1". Plan names, prices, features and links are placeholders.
- **Price formatting.** I used `Intl.NumberFormat("en-US", USD)` with no cents for whole numbers. The visible period label is "per month", not "/mo", so screen readers read it naturally.
- **Accessibility.** The lists are `ul role="list"`, which some lint configs flag as a redundant role. Each CTA has `aria-describedby` pointing at its plan title, so links like "Get started" are distinguishable. The heading levels are an h2 section heading with h3 CardTitles, which assumes the page already has an h1.
