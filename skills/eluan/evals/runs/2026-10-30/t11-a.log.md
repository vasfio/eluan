## Decisions I was unsure about

- **Shape of the answer.** I can't see the existing root, so the default export is a drop-in replacement for the root `EluanProvider` that passes its other props straight through. I did not write a whole `App`.
- **Shades.** The hover, active and focus shades are derived by hand: same hue (164°) at a different lightness. `@eluan/theme-generator` isn't installed and I can't run it.
- **Dark mode.** `createTheme` is mode-agnostic: the docs say it emits one rule, light-mode only. So I picked values that work in every mode (white text on brand fills, a mid-tone focus ring) instead of writing mode-scoped CSS.
- **Focus ring.** I overrode `--interactive-border` because the docs call it "the system-wide focus-ring colour". The token table also labels it "Focus / default border", so it may tint resting input borders green too.
- **Selected state.** I overrode `--interactive-bg-selected` / `--interactive-fg-selected` as a pair. I could not check which components use them, or whether any component puts selected-bg behind a non-selected fg (that would fail contrast).
- **`--action-primary-fg-selected`.** I included it. It appears in xray-showcase/config.ts but not in the tokens page list. If `createTheme` validates token names strictly, it could be rejected.
- **Focus ring colour.** I chose #3D8F79 over the exact brand hex so the ring clears 3:1 on white and on dark surfaces. I couldn't verify the real hex of mono-800/900/950 or teak-100 (dim), so the dark-mode and dim margins are assumptions.
- **Corners.** "Rounder corners" = `defaultCurves="sweeping"`, the only scale rounder than the default `slight`. I didn't override the `--curves-*` tokens directly.
- **Persistence migration.** I assumed three things:
  - with `persist`, stored values beat the `default*` props (from the SSR section of the docs);
  - the theme value is stored as a plain name (the docs' inline script reads it raw);
  - EluanProvider reads storage at or after its first render.

  The one-time rewrite of `slight` → `sweeping` could override a user who deliberately picked `slight` in an app setting. It runs during render (through a lazy `useState` initialiser), which is unusual.
- **Possible pre-hydration flash.** If the app uses the docs' pre-hydration script, it writes `eluan:theme` straight into `data-theme`. For a custom theme name like `brand`, that would drop the `minimal` base until the provider mounts. Not addressed; it's outside this file.
- **Theme name.** `brand` is a placeholder. I don't know the company name.
- **`"use client"`.** Added on the assumption the app might be Next.js App Router. It does nothing elsewhere.
- **Left neutral on purpose:** secondary/tertiary buttons, `--interactive-fg` (links, and probably input text), status colours, dataviz and disabled states.
- **`extends`.** Left out, since it defaults to `minimal`.
- **Props type.** Typed via `React.ComponentProps<typeof EluanProvider>` because the docs don't name a props type. This assumes `persist` and `children` are props on it, as the docs show.
