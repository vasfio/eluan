## Decisions I was unsure about

- Built Cards in a grid, not a Table, even though the teammate said "pricing table": page-layout.md and card.md both say plans side by side with one recommended are Cards.
- Badge variant `important` for "Recommended" instead of the card.md example's `informative`: badge.md lists `important` for "Featured"-style emphasis and `informative` for neutral status like "Scheduled".
- Non-recommended cards use `elevation="none"` (elevation.md rule 3: flat layouts) instead of the card.md example's `"sm"`; the recommended card uses `"md"` as card.md suggests.
- Price is `Typography variant="body" step="4" weight="semibold"` instead of the card.md example's `variant="title"`, because typography rules say one `title` per page and three prices would break that; unsure whether `step` + `weight` is the intended path for a large non-heading figure.
- Responsive grid uses `repeat(auto-fit, minmax(min(100%, calc(var(--size-4xl) * 2)), 1fr))`; no width or breakpoint token exists, media queries can't read tokens, and multiplying a size token may break the spirit of spacing.md rule 6 ("don't invent a step with calc"). It also gives a 2+1 layout at mid widths, so the recommended card isn't in the middle there.
- An inner `div` with `display: flex; height: 100%` sits between Card and its parts so CardFooter pins to the bottom and the buttons line up. Relies on percentage height resolving inside a stretched grid item; the docs neither endorse nor forbid a wrapper inside Card.
- Assumed CardHeader spaces its title row and CardDescription itself (the card.md example does the same); its internal gap isn't documented.
- Assumed Eluan's CSS doesn't reset `<p>`/`<ul>` margins, so I set `margin: 0` / `padding: 0` on my own elements.
- Added lucide `Check` icons to feature rows (aria-hidden, `--size-xxs`, inherited colour), aligned with `alignItems: "baseline"`; this is my own visual choice, not something the docs require.
- `role="list"` on the unstyled `<ul>` to keep list semantics in Safari/VoiceOver.
- CTAs are `type="button"` Buttons calling an `onSelectPlan(planId)` prop rather than links (`Button asChild` + `<a>`); unknown whether the teammate's flow navigates to a signup URL or opens checkout in-app.
- Used a single `recommendedPlanId` prop (default "pro") instead of a per-plan `recommended` flag, so at most one primary Button can render.
- Card has `role="article"` with `aria-labelledby` pointing at CardTitle (and the Badge for the recommended plan, giving "Pro Recommended"); CardTitle gets `role="heading" aria-level={3}` under the section's `h2`. The section heading is `h2`; if this is the whole page it should be `h1`.
- Price note copy "per user per month" instead of "/ month" so screen readers don't say "slash"; plan names, prices and features are placeholders.
- Added an `// eluan: composed, ...` comment even though Card is the documented answer here; unsure whether that comment is meant only for real gaps.
