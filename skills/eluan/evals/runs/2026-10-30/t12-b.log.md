## Decisions I was unsure about

- Control choice: went with Switch because theming.md's "Choosing a value" table names it for "a dark mode toggle". I considered a SegmentedControl (Light / Dim / Dark) since Eluan has three modes, but didn't, because the task says "toggle" and the docs settle it.
- Dim mode: the documented example uses `setMode(on ? "dark" : "light")`, which would wipe out a "dim" choice when dark is turned off. I added a ref that remembers the last non-dark mode and goes back to it. That's a small departure from the doc example. If the app never uses dim, it does the same thing as the example.
- I wasn't sure whether `mode` from `useEluanTheme()` gives the resolved OS scheme before the user has picked a mode (theming.md says the Provider "follows the OS colour scheme until the user picks a mode"). If it only gives the stored or default value, the switch could show off while the page is dark. I couldn't check this without the source, which was off limits, so I trusted the Provider.
- Typing: the skill doesn't name an exported mode type, so I derived it with `ReturnType<typeof useEluanTheme>["mode"]` rather than guess an import name.
- Label: I used a visible `Label` ("Dark mode") tied to the switch through `htmlFor`/`id` rather than `aria-label` alone (the theming.md Do example uses `aria-label` only). switch.md allows either. I went visible for clarity.
- Order: Label first, Switch after. switch.md allows either order for a single compact toggle.
- Gap: `--spacing-sm`, from spacing.md's "space between inline items" row (xs to sm). I didn't use the `--spacing-lg` + space-between settings-row layout because this is a standalone control, not a settings list.
- `display: inline-flex` rather than `flex`, so it fits inline in a header or toolbar. Where it actually goes is up to the teammate, since I couldn't see the app's layout files.
- IDs: used `React.useId()` instead of a fixed id, so two instances (e.g. desktop header and mobile menu) don't clash. This assumes React 18+.
- No icon, even though lucide-react is installed. switch.md's content guidelines say to label the setting, and an icon wasn't needed, so I didn't read foundations/iconography.md.
- I didn't read foundations/colour.md or foundations/typography.md, because I made no colour or text-style choices (Switch and Label set their own). I didn't read patterns/forms.md (linked from switch.md) either, because the decision tree sent this task to theming.md, not forms.
- No loading or disabled state: `setMode` is synchronous local state as far as the docs say, so switch.md's async-save pattern doesn't apply.
