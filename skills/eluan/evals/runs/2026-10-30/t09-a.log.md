## Decisions I was unsure about

- **Row menu:** I used `ActionPopover` rather than building one from `DropdownMenu`. Its docs describe it as a row-level menu for tables, built on DropdownMenu. The catch: it only exposes `items` / `align` / `side` / `aria-label`, so I can't set `modal` or focus callbacks.
- **Default export:** it is a container (`UsersTableContainer`) that holds placeholder users in local state. The reusable piece is the named `UsersTable`, which takes props. I did this so the default export renders without props, but production code would normally not ship sample data.
- **Inline styles instead of StyleX:** I styled the few plain elements with `style` objects that use tokens, not `stylex.create`. I couldn't confirm the app has the StyleX compiler set up, and the tokens page says a `style` attribute is a valid way to use tokens.
- **Spacing token:** I used `--spacing-xs`, not the `--space-200` style used throughout the docs demos. globals.css shows `--space-*` is defined by the docs site, not by the package.
- **Unverified props on table parts:** I assumed `TableHead` passes `aria-sort` through to the `<th>`, and `TableCell` passes `colSpan`. The Table docs list no props. Other components say they "extend standard HTML props except className/style".
- **Sort button alignment:** the sort control is `Button variant="ghost" size="sm"` inside `TableHead`. Button's own padding will likely push header labels slightly right of the cell text. I can't correct it because Button takes no `className`/`style`, and the docs don't give its padding.
- **Button variant:** I picked `ghost` over `mutedGhost` for the header buttons. It's a guess, since I don't know the header text color.
- **Sort icon spacing:** I gave the icon `marginInlineStart: var(--spacing-xs)`. If Button already adds a gap between children, the space will be doubled.
- **Sort behavior:**
  - Clicking toggles between ascending and descending; there is no unsorted third state.
  - A newly clicked column always starts ascending, including "Last active" (oldest first).
  - The default sort is Name ascending.
- **Role and status order:** they sort by a fixed rank (Owner→Viewer, Active→Suspended), not alphabetically.
- **Never-active users:** a null "Last active" stays at the bottom in both directions.
- **Tie-break:** equal rows fall back to name, then id, so sorting stays stable.
- **aria-sort placement:** only the sorted column gets `aria-sort` (the WAI-ARIA pattern). The header button's name is just the column label, and the icon is `aria-hidden`.
- **Badge colors:** active = `positive`, invited = `informative`, suspended = `caution`. I chose `caution` over `destructive` for suspended.
- **Menu items:**
  - Suspend and Reactivate swap based on status. Delete is marked destructive.
  - Owners can't be suspended or deleted, and invited users can't be suspended. These items show as disabled with no explanation.
  - There is no Edit, because there's no edit UI to call. There is no "Copy email", because I didn't check how Toast feedback works (I didn't read the toast docs).
- **Delete confirmation:**
  - The confirm Dialog lives inside `UsersTable` and calls `onDelete` only after confirmation.
  - `onDelete` may be async. While it runs, the buttons are disabled and Escape or an outside click won't close the dialog.
  - If it rejects, the dialog stays open and the rejection goes unhandled, so the caller is expected to handle errors.
- **Opening the dialog from a menu item:** the Dialog is controlled and has no `DialogTrigger`. The docs only show the controlled form with a trigger. Opening it from a menu item's `onClick` may hit Radix's known focus-return or stuck `pointer-events` issues. After Cancel, focus may land on `<body>` instead of the row's menu button. I couldn't test this.
- **Dialog text while closing:** the delete target is kept in its own state so the dialog text doesn't go blank while it animates closed.
- **Menu icons:** I passed `aria-hidden` icons to ActionPopover items with no extra spacing, assuming the component spaces icons itself (the docs demo passes a bare `<Pencil size={16} />`).
- **Table name:** I used a visible `TableCaption` ("Users", can be overridden by a prop) as the table's accessible name. I avoided `aria-label` on `Table` because the docs call it a scroll wrapper, so the label might end up on a div rather than the `<table>`.
- **"Actions" header:** it is hidden visually with a hand-written screen-reader-only style, because the component list has no VisuallyHidden.
- **Muted text:** email, "Never" and the empty state use `color: var(--container-fg-alt)` on a span, not `Typography tone="muted"`. Typography would also set its own font size, which could clash with the table's text size.
- **Dates:** they are formatted with `Intl.DateTimeFormat(undefined, { dateStyle: "medium" })`. If the server and browser locales differ, server rendering could cause a hydration mismatch.
- **`"use client"`:** I added it at the top of the file, as the docs demos do. It does nothing outside Next.js.
- **Not verified:** none of this was run or type-checked, as the task forbids it. The derived types (`React.ComponentProps<typeof ActionPopover>["items"][number]` and Badge's `variant`) assume these components export normal prop types.
