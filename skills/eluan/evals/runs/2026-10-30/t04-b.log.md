## Decisions I was unsure about

- Scope: I built a reusable `SettingsForm` wrapper (the caller passes the fields as children, plus `onSave`) instead of making up specific settings fields. That kept the job to the save feedback and meant I didn't need to read input/label/switch files. The catch is that the default export renders nothing useful without children.
- I didn't mount `<Toast />` in this file. The docs say to mount it once at the root, not per page, and I can't edit the root. So the feature depends on the root having it, which the task doesn't confirm. I put that prerequisite in a comment at the top.
- `toast("Settings saved")` vs `toast.success(...)`: the teammate said "success message", but toast.md maps routine "Settings saved" to plain `toast()` and keeps `toast.success()` for successes worth emphasising. I went with `toast()`.
- I added a fixed toast `id` ("settings-saved") so repeated saves update one toast instead of stacking copies. The docs mention reusing an id but don't recommend it here; this is my own judgement.
- I added an inline destructive Banner with `role="alert"` for a failed save, which the task didn't ask for. I treated it as basic production error handling, as feedback.md and toast.md recommend. I wrote the copy myself, following banner.md's content guidelines.
- I pass `FormData` to `onSave` so uncontrolled fields also work. Controlled callers can ignore it, but it makes the API a bit wider than strictly needed.
- `sonner` can't be installed here. I documented it as a required direct dependency (range ^2.0.7, from toast.md) in a comment.
- Busy state: I added Spinner `size="sm"` with `aria-hidden`, the label changes to "Saving…", and the button gets `disabled` and `aria-busy`, as button.md and spinner.md say. I also added an `if (saving) return` guard against double submits, which is my own addition.
- Layout tokens: `--spacing-lg` between form children (from forms.md and spacing.md) and `--spacing-sm` for the actions row gap. With a single button that gap does nothing, but it stays right if a Cancel button is added.
- I left the icon off the error Banner, so I didn't read foundations/iconography.md. I also didn't read foundations/colour.md or typography.md, since I made no colour or text-style choices outside the components.
- I read patterns/forms.md even though the decision tree sends "show a message" to feedback.md, not forms. I read it because the component is a form shell. Someone could argue it was outside the strict routing.
- I didn't add `noValidate`, so the browser's native validation on the caller's fields still works. The wrapper can't know what validation the caller wants.
