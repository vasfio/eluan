## Decisions I was unsure about

- I used `variant="caution"` for "warning". There is no `warning` variant, and caution is the closest semantic match. It's the variant the docs and showcase use for nearing-limit alerts.
- I used `position="top"` for "across the top". The docs say this makes it `position: fixed` and edge-to-edge. That means it will sit over the top of the page content and any sticky `Header`, and nothing in the docs says Banner reserves space for itself. I did not add a spacer or offset because I don't know the app's layout. If it overlaps, the alternative is the default inline banner rendered as the first child of the app shell.
- I used `TriangleAlert` from lucide-react (`size={16}`, `aria-hidden`), copying landing-showcase.tsx. I'm assuming the installed lucide-react version exports `TriangleAlert`. Older versions only have `AlertTriangle`.
- I made the day count a `daysLeft` prop defaulting to 3, with singular/plural text, instead of hard-coding "3 days". It's a small step beyond the literal ask.
- I made it not dismissible and gave it no "Upgrade" action, because neither was asked for and there's no upgrade route to link to. A product decision could reasonably want either.
- I added no `role`/`aria-live`. The docs don't say what role Banner renders, and overriding it blind could clash. A message that is present on load doesn't need a live region anyway.
- I passed no `className`/`style`. The getting-started page says styling is closed. The Banner props section says it "extends all HTMLDivElement props", which looks inconsistent, but I didn't need either.
- I added no `"use client"` directive, because the component has no hooks or handlers. I'm assuming Banner marks itself as a client component if it needs to.
