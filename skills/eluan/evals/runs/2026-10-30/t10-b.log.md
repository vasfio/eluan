## Decisions I was unsure about

- The existing top nav wasn't visible, so I wrote the whole Header. The logo ("Northwind"), the four nav links and the `currentPath` active-link logic stand in for whatever the real nav already has. In the real repo I'd add only the `actions` slot and `mobileBreakpoint` to the existing Header.
- The search scope and label are a guess ("Search projects"). The docs reject "Search...", but I don't know what the app searches. If search is site-wide, the label should change.
- What search does: I exposed an `onSearch(query)` callback prop and didn't navigate directly, because I don't know the router. The alternative was a native `<form action="/search">` with `name="q"`.
- Empty or whitespace-only queries are ignored, and the query is trimmed before `onSearch`.
- I used `<form role="search">` because search-input.md says to wrap a site-wide search in a form, while header.md's examples use `<div role="search">`. Its `onSubmit` calls preventDefault and runs the search, as a safety net. SearchInput already handles Enter, so it shouldn't fire twice.
- I chose SearchInput over CommandSearch (Cmd+K). Header renders `actions` twice while the mobile menu is open, which would break the "one CommandSearch per page" rule, and CommandSearch ignores `onSearch`/`onValueChange`.
- I set no width on the search wrapper. No token fits (the largest `--size-*` is 120px) and px/rem are forbidden, so the field uses its natural width in the bar and full width in the mobile menu column. It may look narrower than a designer wants.
- I set `mobileBreakpoint="lg"`, following header.md's guidance for a search field in `actions`. This changes when the existing nav collapses (1024px instead of 768px).
- I left `sticky` off so the nav's current behaviour doesn't change, even though the header.md example uses it.
- For the logo link I copied header.md's example: inline `color: inherit; textDecoration: none` on my own `<a>`, with Typography `variant="lead" weight="semibold"`. I didn't read foundations/typography.md or colour.md for this, and relied on the component doc's example.
- After a search from the mobile menu, the Sheet stays open. Header has no prop to close it from outside, so I left it.
- No `debounceMs`. Site search runs on Enter, not as you type.
- On a search results page the field isn't pre-filled from the URL (no `initialQuery` prop). I kept the change small.
- `active` uses exact or prefix matching on `currentPath`. On pages outside the nav (for example a search results page) no link is active.
- I didn't read components/input.md, even though SearchInput is built on Input. search-input.md seemed to cover everything I used.
