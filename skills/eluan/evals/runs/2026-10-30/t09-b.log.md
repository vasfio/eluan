## Decisions I was unsure about

- Row menu: I used DropdownMenu rather than ActionPopover. The SKILL index suggests ActionPopover for a row's "more actions", but table.md rule 4 says DropdownMenu, and my menu has a submenu and a separator.
- "Change role" is a submenu of DropdownMenuRadioItems that applies at once. dropdown-menu.md warns against building a form field out of menu radio items. I read that warning as being about form values, not immediate actions, but it's a borderline call.
- "Suspend user" / "Reactivate user" uses the default tone and has no confirmation. It is reversible and the Badge shows the result. You could argue it "revokes" access and should be destructive and confirmed.
- I left out row selection checkboxes, pagination, filtering and a toolbar, because the task asked only for sorting and a row menu. The table.md example does include selection.
- State lives in the component, seeded from an optional `initialUsers` prop that defaults to sample data. There are no API callbacks and no async, loading or error handling. In a real app, the parent would own the data and pass handlers in.
- I gave no feedback after an action (no Toast). Each action changes the table where you can see it (role text, status badge, row removed), and I didn't want to assume a Toast is mounted.
- The email under the name uses `Typography variant="caption" tone="muted" as="div"`. The table.md example uses a raw div coloured with `--container-fg-alt` that inherits the cell's size and weight. I followed the Typography rule ("set app text with Typography"), so the email renders one step smaller.
- "Never signed in" shows an em dash, following the table content guideline. "Never" might read better, and a screen reader may announce the dash oddly.
- Focus management: the remove Dialog opens from a menu item, so I handle `onCloseAutoFocus` myself (dialog.md rule 4). After Cancel, focus goes back to the row's trigger. After Remove, it goes to the neighbouring row's trigger, or to a `tabIndex={-1}` empty-state wrapper if no rows are left. The neighbour and empty-state fallbacks are my own; the docs don't cover a trigger that no longer exists.
- I put the trigger ref on `DropdownMenuTrigger` (a Radix part that forwards refs) instead of on Button, because button.md doesn't say whether Button forwards refs.
- I didn't add the menu-to-dialog focus/pointer-events workarounds sometimes needed with Radix, such as `modal={false}` or preventing the menu's onCloseAutoFocus. I followed dropdown-menu.md rule 5 exactly. I couldn't run the code to check for a focus race.
- Empty state: the heading is `as="h2"` because the page's heading structure is unknown. It has no action, because there is no invite flow to link to. The pattern allows "one action, or none".
- Sorting: Role sorts alphabetically. That happens to match the privilege order Admin, Member, Viewer, but it would stop matching if a new role were added. Last active starts descending (most recent first) on its first click. Never-signed-in users stay last in both directions. Ties break on name, then email. The default sort is Name ascending.
- The sort Button is ghost `sm` inside the TableHead, as in the table.md example. The Button's own padding means header labels don't line up exactly with cell text. I didn't correct this, because that would need calc or negative margins on spacing tokens.
- The actions column header is an empty `TableHead` with `aria-label="Actions"`, copied from the table.md example, because Eluan documents no visually-hidden text utility.
- Dates use `Intl.DateTimeFormat(undefined, { dateStyle: "medium" })`. That follows the viewer's locale, but it could cause a hydration mismatch under SSR.
- I didn't hide low-priority columns on narrow screens. table.md suggests it, but I relied on the wrapper's horizontal scroll.
- The icon is named `Ellipsis`, as in the table.md example. dropdown-menu.md uses `MoreHorizontal`. Which name exists depends on the installed lucide-react version, which I couldn't check.
- Dialog copy: the title is "Remove {name} from the workspace?", the confirm button "Remove from workspace", and the description says they'll need a new invite to get access back. The re-invite behaviour is my assumption about the product.
