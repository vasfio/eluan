## Decisions I was unsure about

- Tabs vs SegmentedControl: I chose `Tabs`. Each option shows a different content panel, and the SegmentedControl docs call it "the picker only", which is not what this needs.
- Uncontrolled `defaultValue="overview"`, with no `value`/`onValueChange`/URL sync props. Nothing in the request asked for those, so I left them out to avoid over-building. A teammate may want deep-linking later.
- Panel content: I don't know the real content, so each panel is a small in-file helper: a `Card` with title, description and a muted empty-state line. This follows the docs pattern of a Card inside TabsContent. Placeholder copy in shipped code may not be what the teammate wants; they may prefer a component that takes panel content as props.
- No extra spacing wrapper between `TabsList` and the panels. The tabs demos and the landing showcase put content straight into `TabsContent`. The x-ray showcase adds `padding-top: var(--spacing-lg)` (`.tabBody`). I can't see whether `TabsContent` has built-in top spacing, so the panels might sit tight against the list.
- No StyleX and no inline styles in my file. The installation page says consumers don't need a StyleX setup, so importing `@stylexjs/stylex` could break the build if the app lacks the compiler. Eluan components don't accept `className`/`style` anyway. Using Card and Typography meant I needed no custom layout CSS.
- No lucide icons in the triggers, even though lucide-react is installed. No docs example puts icons in a `TabsTrigger`, and I can't check how the trigger lays out icon plus label without styling it myself.
- No `aria-label` on `TabsList`. The docs examples don't use one, and any label I picked ("Project sections" and so on) would guess at context I don't have. APG recommends labelling a tablist, so this is a possible a11y gap.
- Added `"use client"` to match the docs demo files. I can't tell whether `@eluan/core`'s Tabs has its own client directive, which matters for Next.js App Router. Other bundlers ignore the directive, though Rollup/Vite may warn about it.
- Used `Typography tone="muted"` (default variant `body`, which renders a `p`) for the panel text instead of a raw `<p>` with token styles, as the tokens page suggests for React.
- The Tabs docs snippet shows `<Input label=…>`, but the demo uses `FormLabel` + `Input id`. The two disagree. I put no form fields in Settings, so this didn't affect my code, but it's a docs inconsistency.
- `CardTitle` renders an `h3` by default. The right heading level depends on the host page, which I can't see.
