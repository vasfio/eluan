## Decisions I was unsure about

- API shape: I made a reusable component with a required `onClose` callback instead of wrapping it in `SheetClose`/`DrawerClose`. The teammate didn't say which panel primitive they use, so the caller owns the open state. The docs show `SheetClose asChild` but only show `DrawerClose` with text children, so I couldn't confirm `asChild` works on DrawerClose.
- No `forwardRef` and no spreading of other props: this keeps it simple, but it means `<SheetClose asChild><ClosePanelButton/></SheetClose>` won't work. Callers would use `onClose` instead.
- Duplicate X risk: the docs don't say whether `SheetContent` or `DrawerContent` already render a built-in close button. If one does, this button would duplicate it inside those primitives.
- `variant="ghost"`: every icon-only button in the docs uses ghost (one uses outline). I didn't consider `mutedGhost`/`fadedGhost` because the docs don't describe when to pick them.
- `size="icon"` with a 16px lucide icon, following docs/layout.tsx, search.tsx and the drawer docs. `iconSm` with 14px was the other option, used for denser rows.
- No Tooltip: the Tooltip docs suggest pairing one with icon-only buttons, but a close X is universally recognised and the aria-label already gives the accessible name. A tooltip with the same text would also be announced twice via aria-describedby. I also don't know if EluanProvider already supplies a TooltipProvider.
- `type="button"` set explicitly: the docs don't say what Button's default type is, and a side panel may contain a form.
- Default label "Close panel", overridable through `label` so callers can name the specific panel.
- `aria-hidden` on the icon, following landing-showcase.tsx. Other docs examples leave it off.
- No `"use client"` directive: the app is described as React + TS, not necessarily Next.js RSC, and the component uses no hooks.
- I typed props myself instead of importing a `ButtonProps` type from @eluan/core, because the docs don't confirm such an export.
