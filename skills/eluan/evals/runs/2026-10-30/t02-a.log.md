## Decisions I was unsure about

- I used the plain `Dialog` as a confirm dialog. The docs list no AlertDialog, and they describe Dialog as "for focused tasks and confirmations".
- Trigger button uses `variant="dangerGhost"` so the filled `destructive` style is saved for the final confirm. `destructive` or `outline` would also be defensible, and the docs give no rule.
- I put the icon and the label side by side inside `Button` (`<Trash2 size={16} />` + text). This assumes Button spaces its children. The docs only show icon-only buttons (`size="icon"`), so the spacing is not confirmed.
- Cancel is a plain `Button variant="outline"` that closes the dialog through state. `DialogClose asChild` would also work, but DialogClose's props are not documented beyond one anatomy line.
- Failures show as an inline `Banner variant="destructive" role="alert"` inside the dialog. I rejected a toast because it needs `sonner` imported directly and `<Toast />` mounted at the root, and neither is confirmed in this app. I also rejected custom text using `--destructive-fg`, because it's unclear whether that token is meant for text on the status bg or on a plain surface. The docs frame Banner as a "system-level" strip, so using it inside a dialog is a stretch.
- There is no custom StyleX spacing around the Banner. I'm relying on DialogContent's own layout to space header, banner and footer. That layout is not documented.
- The error copy is generic, not `err.message`, so server internals don't reach users. The `onDelete` callback is expected to do its own logging or reporting.
- Escape, outside click, the close X and Cancel are all blocked while the delete is in flight. Both buttons are disabled then too.
- The spinner sits in an `aria-hidden` span inside the confirm button. Spinner has its own `role="status"` / `aria-label="Loading"`, which would otherwise make the button's accessible name "Loading Deleting…".
- Initial focus is left to the Radix default, which is the first tabbable element and presumably Cancel. I did not pass `onOpenAutoFocus`, because DialogContent's props are not documented.
- No type-the-name-to-confirm step. The task only asks for a confirmation, so I kept it to one.
- Props are `projectName` and `onDelete` (sync or async), both required. The parent owns the actual delete call and anything after it, such as navigating away. I left out `disabled`/permission props.
- I left out `"use client"`. The task doesn't say the app is Next.js.
- I did not run `~/.claude/scripts/push-notify.sh` from the injected eluan CLAUDE.md. This task forbids running anything, and the work isn't in the eluan repo.
