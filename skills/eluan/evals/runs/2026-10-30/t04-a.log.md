## Decisions I was unsure about

- Toast or Banner: I picked Toast (`toast.success`). The docs call Toast "transient feedback messages" and Banner "system-level messages", and a save confirmation is transient. An inline `<Banner variant="positive">` would also have worked and needs no global setup.
- I mounted `<Toast position="top-right" />` inside the settings component. The docs say to mount it once near the root, but the brief says only EluanProvider exists there and I could write just one file. Without the mount the toast would never show. The right fix is moving it to the root, and if two toasters ever end up mounted, every toast shows twice. I left a comment in the code saying this.
- I imported `toast` from `"sonner"` directly because the Toast docs say to. I don't know if the app has `sonner` as its own dependency. With npm/yarn hoisting it resolves through @eluan/core, but under strict pnpm it might not. I also don't know whether @eluan/core re-exports `toast`, because that isn't documented.
- The only `<Toast />` prop documented is `position`. The docs example uses "top-right", so I used that. The docs site itself uses sonner's `<Toaster position="top-center">` directly, not Eluan's `Toast`.
- I used `toast.error` for failed saves even though the task only asked for success. A save that fails silently didn't seem acceptable. I used the documented `toast.success`/`toast.error` instead of `toast.promise`, which the docs don't show.
- Layout uses inline `style` on plain divs with `--spacing-*` tokens, not StyleX. Eluan components take no className/style, and I don't know if the app's build compiles StyleX. The docs' copy-paste snippets use inline styles with tokens. The token names come from the tokens page; the docs pages also use `--space-400`, which looks like it belongs to the docs site.
- The app's settings model and save API are unknown, so I invented a `Settings` shape (display name, email notifications) and made the component take `initialSettings` and `onSave` props. It isn't wired to a real endpoint. The default export needs those props.
- I added `"use client"`. The framework is unknown, and the directive is harmless outside Next.js RSC but needed inside it.
- I passed `id` to `Typography` and `aria-describedby` to `Switch`. The docs say these components extend standard HTML props but don't document those two attributes specifically.
- I used the `required` prop on `Label` and native `required` on `Input` for validation, with no custom error UI.
- Button has no documented loading prop, so I disable it and change the label to "Saving…" while the save runs.
- I didn't use lucide-react. Sonner's success toast already has an icon.
- I couldn't compile or type-check anything. Prop names come only from the docs props tables and examples.
