## Decisions I was unsure about

- **Default export:** I made it a whole `TopNav` built on Eluan's `Header`, because I can't see the app's existing nav. I also exported `NavSearch` on its own so it can be dropped into an existing bar instead.
- **Which component:** I chose `SearchInput`, the best-documented option (full props table). I passed on `CommandSearch`: its shortcut and `onSearch` behaviour are only loosely described and it has no props table. I passed on `AutocompleteSearch` because I have no suggestion data. I passed on `Input type="search"` because it lacks the clear and submit handling.
- **When it searches:** `searchOnEnter` fires on Enter instead of the 300ms debounced live search. I assumed a global nav search navigates to a results page, where firing on every pause would be wrong.
- **`role="search"` on a div, not a `<form>`:** the docs don't say whether `SearchInput`'s Enter handling calls `preventDefault`. A form could double-fire or reload the page.
- **`aria-label` on `SearchInput`:** I assumed it is forwarded to the input. Input's docs say it extends all `HTMLInputElement` props. For `SearchInput` I only inferred this from `placeholder` and `autoFocus` being passed in the demos.
- **`onClear` also resets local state:** I'm not sure whether the clear button already calls `onValueChange("")`. Resetting twice does no harm.
- **Field width:** I used a literal `18rem` that can shrink. No Eluan width token fits: the `--sizing-*` scale stops at 6rem and the `--spacing-*` tokens are gaps.
- **Mobile layout:** the docs don't say what happens to `Header`'s `actions` slot below `mobileBreakpoint`. The field may crowd the bar on phones, and I can't check because I can't run anything.
- **Placement:** the search sits in the `actions` slot, ahead of any other actions. `Header` has no documented slot for a centred or middle-of-bar search.
- **No keyboard shortcut** (⌘K or `/`) to focus the field. I left it out to avoid gold-plating and because the docs don't say where `SearchInput`'s ref points.
- **Empty queries:** they are ignored, and queries are trimmed before `onSearch` is called.
- **`"use client"`:** included because the docs demos use it and it is harmless outside Next.js. The app's framework is unknown.
- **Current query:** the field doesn't pick up an existing query (for example `?q=` in the URL), so it starts empty even on a results page.
- **`NavItem` shape:** I didn't see the full type. The Header page links to a `/docs/components/header-navigation` page that doesn't exist in the docs source. I only pass `items` through, so the exact shape doesn't matter here.
- **`sticky`:** passed through as an optional prop, so `Header`'s default (`false`) applies unless the caller sets it.
