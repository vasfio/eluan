## Decisions I was unsure about

- **Layout styling.** I used typed inline style objects instead of StyleX for the layout wrappers.
  - I can't tell whether the app runs the StyleX compiler itself. The installation page says consumers need no build setup.
  - The consumer-facing snippets in the docs (Button, Getting Started, Modes) put layout in `style={{ ... var(--token) }}`.
  - If the app does compile StyleX, `stylex.create` would be the more idiomatic choice.
- **No Card.** Card's sub-components take no className/style, and I couldn't confirm that CardHeader/CardTitle would centre. I built my own dashed `<section>` frame instead.
- **Tokens.**
  - Colours come from layer-3 `--container-*` tokens. not-found.tsx uses the layer-2 `--backgrounds-*`/`--foregrounds-*` instead, but the tokens page says components consume layer 3.
  - I avoided the aliases that only exist in the docs site: `--space-*`, `--muted-fg` and `--border`.
- **Icon tile size.** I used the layer-1 primitive `--sizing-size-48`. The semantic `--size-sm/md/lg` aliases exist, but the docs never give their values.
- **Literal sizes.** `minHeight: 20rem` and `maxWidth: 28rem` are hard-coded because the docs have no layout-width or height tokens.
- **Heading.** I used `variant="subheading"` with `as="h2"`, assuming the dashboard page already has its own `<h1>`. Variant "heading" (step 3) might be wanted instead.
- **Heading id.** The heading id goes in through Typography's `id` prop. The docs say Typography extends HTMLElement props, so I assumed `id` is forwarded to the rendered element.
- **Icon spacing in Button.** I assumed Button spaces an icon child and its label itself; the docs examples add no spacing of their own.
  - Icon sizes: 16px in the button (as in not-found.tsx), 24px with strokeWidth 1.75 in the tile. These are judgement calls.
- **Redundant aria-hidden.** `aria-hidden` on the lucide icons may be redundant if lucide's default already sets it.
- **`"use client"`.** Added in case the app uses the Next.js App Router. It does nothing elsewhere.
- **Version requirements.** `satisfies` needs TypeScript 4.9 or later; `useId` needs React 18 or later.
- **Invented copy and API.**
  - The props (required `onCreateProject` callback, optional `learnMoreHref`) are my own; the task gives no product details or routes.
  - The secondary action is a plain `<a>` through `Button asChild`, not the app's router Link, because I don't know which router the app uses.
- **Visual treatment.** The dashed border and the centred layout are my own choices; the docs have no empty-state pattern or EmptyState component.
