## Decisions I was unsure about

- No success Toast after deleting: feedback.md says to use a Toast when the result may not be visible, but `sonner` isn't confirmed as installed and I can't install it, and after a delete the caller usually navigates away or removes the row, so the result is visible. I left success feedback to the caller.
- Description copy is generic ("the project and all of its data"). dialog.md asks you to name what else is lost (for example "14 environments"), but I don't know what a project contains in this app.
- Component API: `projectName` + `onDelete: () => Promise<void>`. A resolve closes the dialog, a reject shows the error. Navigation after a successful delete is left to the caller. A teammate might have expected a router call or a mutation hook inside the component.
- Trigger is `variant="dangerGhost"` with a Trash2 icon, as in dialog.md's example. `destructive` is kept for the confirm button only (button.md Rule 5). Unsure whether the host screen wants a more prominent trigger, for example in a "danger zone" settings section.
- Error reporting: an inline `destructive` Banner with `role="alert"`, placed in the dialog body between header and footer. feedback.md only covers form-level failures; using it inside a Dialog is my extrapolation. The error copy doesn't surface the error itself and nothing is logged.
- The confirm button is `disabled` + `aria-busy` while deleting, per the Button and Spinner docs. A focused button that becomes disabled can lose focus, and I don't move focus back after a failure; I rely on the alert Banner being announced.
- Cancel is disabled and `onOpenChange` is ignored while the request runs (Escape, scrim and X do nothing), following dialog.md's example. The trade-off is that a hung request can't be dismissed.
- The error state is cleared when the dialog reopens and when a retry starts, not when it closes. The result looks the same either way.
- Inline `style` on the Lucide icons (`--size-xxs`). Rule 7 bans style on Eluan components, not on icons, and the docs' own examples do this. A shared `iconStyle` constant is used for both icons.
